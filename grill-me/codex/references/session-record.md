# Compact session record

Adapt this structure to the session; omit empty sections. Keep enough history to resume and explain decisions without producing a transcript. Scale detail to the discussion. Use clear topic labels; stable IDs help only when dependencies are substantial.

```markdown
# Grill: topic
Updated: date
Status: exploring | ready | paused | blocked

## Goal and boundaries
Desired outcome, current framing, material constraints, scope, and any depth budget.

## Decisions
- Topic — agreed / tentative / resolved / superseded.
  Choice or clarification; rationale; alternative considered; relevant date.
  Dependencies or superseded decision, when material.

## Evidence and assumptions
- Claim; sourced fact / user report / preference / working assumption / unknown.
  Source location and freshness where relevant; confidence or limitation;
  what would resolve it and which decision depends on it.

## Open and deferred concerns
- Topic; open / consciously deferred; unresolved question; consequence if ignored;
  next evidence or action; owner or revisit trigger where known.

## Success and rejection conditions
- Observable check, qualitative rubric, threshold, or experiment;
  evidence needed and evaluation point when relevant.

## Discussion trail
- Question or topic → substantive answer, reasoning, and resulting change.
  Record corrections explicitly; mark outdated conclusions superseded.

## Handoff
Current direction; next action and prerequisite; authorized continuation or
remaining user decision. Distinguish ready from paused or blocked.
```

Do not represent a proposal as an agreement or an untested condition as satisfied. On resumption, review changes to pivotal context before reusing earlier conclusions. If using a conversation checkpoint, present the complete compact record when pausing or closing so the user can retain it.
